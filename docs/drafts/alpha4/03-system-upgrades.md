# 03 · 五特性审计与系统升维改造

> 方法：数值策划 skill 的五特性模型——任何数值模块都应回答：**生成**（从哪来）/ **成长**（怎么变强）/ **消亡**（怎么退场）/ **变化**（受什么环境波动影响）/ **联系**（和谁耦合）。
> 审计结论先行：现有模块「生成/成长/联系」三维健康（bonuses 聚合器是优秀的联系底座），**消亡与变化两维系统性为零**。本篇 8 项改造全部围绕补维，不推翻 alpha3 结构。

## 2. 改造项

### S1 · 行业景气轮换【变化维 · 主推】

- 规则：每游戏周切时掷一次，金融/地产/高科技各独立状态：景气(+20% 业务量与人脉计入) / 平稳 / 低谷(−15%)；权重 30/45/25。用数组+权重公式（数值 skill 数列表）；
- UI：业务页行业角标 + 周切换 toast；决策器 gap 补位自动偏向景气质押；
- 与天赋网联动：新增可选精华「顺风局」= 当前景气行业业务量 +10%（见 S8）；
- 参数：`boomEnabled(true) / boomScale(0.2) / boomWeights[30,45,25]` 进 SETTINGS_DEFAULT；
- 存档：`career.boom{finance,estate,tech}` 三枚举，迁移幂等默认平稳；
- 工作量 ≈2 天。红线自查：不产生随机失败（只改产量不改成功率）✅。

### S2 · 关系衰减 Lite【消亡维 · 默认 off 旋钮】

- 动机：回应开放问题 #6，但吸取 TBH 教训——放置游戏惩罚离线玩家必死。所以：**默认关闭的后台旋钮**，开启也只做软漂移；
- 规则（decayEnabled=true 时）：入槽且好感 ≥50 的 NPC，连续 3 游戏日无任何互动 → 日切 −1，钳到所在阶段下限（25/50/75 边界不破）；资产化后免疫；微信/朋友圈也算互动（防挂机焦虑）；
- 人脉同步：好感跌破里程碑则人脉计入比例降档（派生值自动跟随，零额外代码）；
- 工作量 ≈1 天（日切钩子已有）。先 off 上线，02 模拟开/关对比后再定默认值。

### S3 · 掉落透明保底 pity【确定性补偿 · 修开放#7】

- 手算依据见 02-H2：稀有装备期望 ≈4000 掉落，实际不可达；
- 规则：两个计数器 `pityRare / pityEquip`
  - `pityRare`：累计 240 次未出稀有品质 → 下次必稀有（计数清零）；辅助型已有的 ×2 权重保留；
  - `pityEquip`：累计 120 次未出装备 → 下次 func 分支内必出装备，且品质至少 fine；
- UI：背包页两条进度条（n/240、n/120），档案卡公示口径——红线 4「掉率透明」的正面案例；
- 存档 v3→v4 新增两字段，迁移幂等；离线结算分段照跑计数；
- 工作量 ≈1 天。

### S4 · 宠物成长三阶【成长维 · 复用计数器】

- 幂函数式阈值（1x/3x/10x 解锁 I/II/III），效果线性递增：

| 伙伴 | I（现阈值） | II（×3） | III（×10） | 效果阶梯 |
| --- | --- | --- | --- | --- |
| 暖手 🐱 | 约会 200 | 600 | 2000 | 好感 +5/+8/+12% |
| 账房 🦜 | 上班 100h | 300h | 1000h | 收入 +8/+12/+16% |
| 拾荒 🐶 | 拾取 500 | 1500 | 5000 | 掉落间隔 −6/−9/−12% |

- 语义不变：仍永久全局、无需上阵、可叠加；只是把「一次性徽章」变成「复利曲线」，III 阶天然锚定 60~90 日长线目标（与 02 §4 校准表对齐）；
- 存档：`pets.unlocked[]` → `pets{ id: stage }` 迁移（旧档 unlocked 映射 stage:1）；条上形象随阶段换色/加配饰（sprites 管线）；
- 工作量 ≈2 天（大头在 sprites 变体）。

### S5 · 成就二阶【生成/成长维 · 零新管线】

- 现有 5 成就各追加 II 阶：goal ×5（摸鱼 5000 次 / 全勤 500h / 拾荒 2500 / 约会 500 / 资产 25），效果 = 一阶的一半再 +一阶（如摸鱼 II：好感再 +2%，合计 +5%）；
- 复用 `checkAchievements` 同一检查器与聚合器注册路径，纯数据表改动，≈0.5 天。

### S6 · 业务风险三角【三角性原理 · 配合基石】

- 现状：豪赌派/稳健派基石改变的是**效率语义**，但模板本身全是确定性的——「赌」没有赌面；
- 改造：模板加 `certainty: 'stable' | 'risky'` 字段；risky 单开工时效率在 [0.7, 1.3] 均匀掷（期望 ×1.0），但基准量 +15% 作风险溢价；每圈层组内 1 条 risky（T3 起）；
- 与既有系统咬合：稳健派保底 50% 对 risky 同样生效（保底后仍可能 <1）；豪赌派满条件 ×1.3 与 risky 高端 1.3 复合 = 上限单，符合「高配高风险高回报」身份；
- 决策器 L2 评分按期望值即可，无需改评分公式；
- 工作量 ≈1 天。红线自查：这是产量方差不是随机失败 ✅。

### S7 · Build 预设 + 试洗券【Hick 定律 · 降低选择成本】

- 成长页新增三套官方预设按钮（广撒网流 / 深耕流 / 跑单流）：一键点亮该流派合法节点子集（校验互斥与门槛），剩余自由点留给玩家；
- 洗点：首次免费保留；新增「试洗券」——每个圈层首通发放一张，下次洗点半价。回应开放问题 #9 且不破坏 PoE 式摩擦感；
- 工作量 ≈1 天（UI 为主，逻辑全复用）。

### S8 · 条件词条扩容（cond 注册新语境）

- COND_FNS（engine.js:210）新增：`boomHot`（当前业务行业景气）、`hasInvite`（存在有效邀约）、`riskyRun`（进行中为 risky 单）；
- 各系预留 1 个「备选精华」位挂新 cond（如识人系·顺风耳：景气行业情报冷却 −20%）——不增树总量，替换现有同位词条文案二选一点亮（沿用暖场的 choice 机制）;
- 目的：让天赋网与 S1/S6 新系统产生**联系维**耦合，而不是平行堆系统；
- 工作量 ≈1 天，可与 S1/S6 合并切片。

## 3. 明确不做（本轮否决项）
