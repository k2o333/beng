# 00 · alpha4 总体迭代方案

> **一句话定位**：alpha3 完成了「结构搭建」（聚合器→职业→天赋网→装备→宠物），alpha4 完成「**校准驱动 + 维度补全**」——先造尺子再调数，把缺失的消亡/变化两维补上，同时不推翻任何已实装结构。
> 详细论证分散在同目录 `01~04`；本文是唯一排期入口。状态：草案，待拍板 D1~D7 后开工。

## 1. 版本目标（三条，全部可验收）

| # | 目标 | 验收方式 |
| --- | --- | --- |
| G1 | 所有核心曲线有校准工具与目标区间 | sim.js 全量跑通，standard 策略 P50 时刻表落入校准区间；`npm run balance` 报告入库 |
| G2 | 长线目标可达且可见 | 稀有装备经 pity 在总裁前可达（ETA 落区间）；宠物/成就有 II/III 阶复利曲线 |

```text
W1 · M1 校准底座（4d）

  ⑧ 存档 v4 合并迁移（0.5d）  ← pity 计数 + pets{id:stage} 一次做完（D7）
  ── 门禁：npm test 全绿 + 新增单测 + v1/v2/v3 旧档无损 ──

  ⑨ 景气轮换 S1 + cond 扩容 S8（2.5d）
```

## 6. 风险清单

| 风险 | 对策 |
| --- | --- |
| 引擎无法无头复用（UI 耦合） | npm test 已证明纯函数层可无头跑；若 step 内有 DOM 触点，先剥离再排 ① |
| sim 结果全面越界，校准变重做 | 只动 02 号旋钮与表数据，禁止顺手改结构；越界超 2 倍的项单独立决策记录 |
| 景气轮换让决策器行为不可读 | gap 补位优先级已天然吃景气；决策日志加景气角标一行说明 |
| 衰减即使 off 也引发焦虑（设置页可见即担忧） | 文案写「实验特性·默认关闭」；档案卡不展示倒计时类信息 |
| 新系统建在未校准数值上 | W3 门禁硬性卡住；⑨⑩⑪ 的参数一律标注「需 sim 复核」 |
