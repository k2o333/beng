# 04 · 排期、决策点与验收基线

## 1. 切片排期

```text
① sim.js 模拟底座（2d）──────────┐
② balance-report 静态报告（1d）──┤→ 产出 H1~H6 判定数据
③ 数据校准 patch（1d）←依赖①②───┘   （动 balance.js 数值，不动结构）
④ 掉落 pity S3（1d）             ← 修开放#7，独立可先行
⑤ 宠物三阶 S4（2d，sprites 为大头）
⑥ 景气轮换 S1 + 词条扩容 S8（2.5d）
⑦ 业务风险三角 S6（1d）
⑧ Build 预设+试洗券 S7（1d）
⑨ 成就二阶 S5（0.5d）
⑩ 衰减 Lite S2（1d，默认 off 上线）
```

- 总量 ≈13 天；①②③ 是其余切片的前置（校准目标表拍板后才能判定新内容数值是否越界）；
- ④⑤⑨ 与 ① 无依赖可并行；⑥⑦⑧ 建议在校准 patch 之后进，避免新系统建在未校准的地基上。

## 3. 验收基线

- `npm test` 全绿；新增单测：pity 触发边界、景气周切与计入比例联动、risky 效率钳制 [0.7,1.3]×保底交互、宠物阶段迁移、衰减日切漂移与资产免疫；
- 存档 v4 迁移幂等：v1/v2/v3 旧档均可无损进入 alpha4；
- `npm run balance` 报告入 `docs/reports/`，H1~H6 全部有「证实/证伪」结论落档；
- sim 全量跑一轮，standard 策略 P50 时刻表落入 02 §4 区间，否则回到 ③ 调参而不是加系统；
- 红线自查（TBH 不做清单）：无交易 ✅ / 无随机失败（S6 是产量方差）✅ / 无数值付费 ✅ / 掉率透明（pity 公示）✅ / 无战斗语义 ✅。

- 本方案落地后，`alpha4/README.md §3` 表格补「已回应」标记并归档。
