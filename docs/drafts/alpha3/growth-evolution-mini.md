# 成长系统最小演进方案（技能 / 物品 / 数值 / 宠物）

> 输入源：TBH 三篇调研（wiki 技能库、gamemad 宠物说明、pejdw 分段加点）+ `start.md` 七系统树 + `longterm-optimization.md`。
> 原则：**不抄战斗，只抄结构**。所有成长最终都服务核心循环「识人 → 关系博弈 → 人脉转业务」。
> 状态：草案，未排期。

## 0. 一条总原则：先立数值底座

TBH 的被动只有两种类型：**固定值** 与 **加算%**，全部技能/装备/宠物共用同一套乘算管线。
我们现在 `perkMul` 是硬编码的散点乘区，后续加任何系统都要重改公式。

**第一步（前置，约半天）**：在 engine 里建一个统一的 `bonuses` 聚合器——
所有来源（成就 perks / 技能 / 装备 / 宠物 / 职业）只往里注册词条 `{attr, kind: flat|add|mul, value}`，
好感、收入、体力、掉落等结算点统一从聚合器取值。存档 v2→v3 迁移一次到位。

## 1. 技能 = 关系天赋网（不做主动技能）

- TBH 的主动技是战斗语义，我们是放置社交游戏 → 只做**被动节点**。
- 结构借鉴 PoE/暗黑2/恐怖黎明/暗黑4（调研与全树拓扑见 `alpha3/04-skills.md`）：
  **支点(9) / 精华(6) / 大节点(3，需本系投入≥5) / 基石互斥对(3 对取 1) / 跨系连携(3)**，
  三分支仍对应识人→博弈→转业务；节点多为条件词条而非白板 +%。
- 点数刻意永远不够：收入 14 点（打工期）vs 全树需求 ≈29 点，洗点收金币摩擦费。
- 文案用 TBH 式 `{0}%` 模板串进 texts.js。
- 技能点来源对齐 start.md 职业主线：**升职/公司升级/圈层首通** 各发 1 点
  （职级/业务量数值口径见 `career-numbers-mini.md`，职业线先于本表实装）；
  解锁门槛按职级分段（对标 pejdw 的 30 前/30-50/50-80：专员期/经理期/总监期各开一档）。
- 复用现有 `checkAchievements` 的检查时机，约 4~5 天。

## 2. 物品 = 从消耗品到「一饰一槽」

- 现状：12 件纯消耗品 + 3合1合成已落地，缺长线持有感。
- 最小步：加 **2 个装备槽**（手表=收益向 / 首饰=社交向）。物品新增 `effect.kind: equip`，
  装备后词条常驻进 `bonuses`（对标 pejdw「首饰打吸血装饰用到毕业」的持有体验）。
- 同名物品品质仍走 fine×1.5 / rare×2 放大，与消耗品共用 qualityRank。
- `longterm-optimization.md` #2 的稀有度光效顺势一起做（同一渲染点）。
- 约 2 天；魔方/自定义词条明确后置。

## 3. 宠物 = 可见的账号级被动层

- TBH 定理照单全收：**永久全局生效、无需上阵、可叠加、无数量上限、越早解锁复利越大**。
- 解锁条件翻译：「累计击杀 N 只怪」→「累计行为 N 次」（累计约会 200 次 / 累计上班 100h / 累计掉落 500 件……计数器 stats 里现成）。
- 与成就 perks 的分工：perks 保持隐藏被动层不动；宠物是**可见收集层**——条上多一只像素伙伴（sprites 管线复用），属性页给一览表。
- 首版 3 只，各对应一资源：金币+% / 全局好感+% / 掉落间隔-%。
- 约 2~3 天；DLC 卖宠物的商业化路线仅记录不实施。

## 4. 数值护栏（从 TBH 差评学到的）

- 掉率/阈值全部进 balance.js 后台参数，档案卡公示口径（坚持 06 校准清单方向）；
- 不做任何交易/市场语义；百分比膨胀设上限（同类加算词条总上限 +100%，超出转为独立乘区）。

## 5. 排期顺序与依赖

```text
① bonuses 聚合器（底座）
   ↓
② 关系天赋网 ──依赖①──┐
③ 装备槽     ──依赖①──┤→ 三者互不依赖，可任意拆分并行
④ 宠物       ──依赖①──┘
```

若只做一件事：先做 **①**；做完②后游戏第一次出现「Build 感」，性价比最高。

## 6. 验收基线

- 存档迁移 v2→v3 幂等，旧档无损；
- 任一词条增删不改结算公式本体，只动数据表；
- tests/test-engine.js 补 bonuses 单测（flat/add/mul 三型叠乘顺序固定且公示）。
